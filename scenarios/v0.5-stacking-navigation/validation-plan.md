# Native stacking and walking validation / 原生叠放与步行验证

Owner2026-11-08 requested implementation and validation in the current owned save after requiring every Native-stackable building/model/host combination. This plan tracks the new work separately from the accepted [first-sail/rocket review](../../releases/v0.5.0/expansion-review-delivery-2026-11-06.md). / 所有者要求全部原生可叠放建筑/模型/宿主组合，并明确要求在当前owned存档实施验证。本轮与已验收首帆/火箭证据分开记录。

## Scope / 范围

- Enumerate the complete Native stacking/model catalog, compatibility edges, rotation transforms, joint offsets, technology limits and storage-attachment aliases. Include storage grades, tanks, lab grades, splitter styles and supported host relations. Treat missing rows as pending. / 完整枚举原生叠放/模型目录、兼容边、朝向转换、接点偏移、科技限制和仓储挂件别名；覆盖储仓等级、液罐、研究站等级、分流器样式及宿主关系，缺项保留待验。
- Validate creation, exact model and reciprocal layer links, one original material debit, layer-specific contents/function and normal save/recovery. / 验证建造、准确模型/双向层连接、原单次扣料、逐层内容/功能与正常保存恢复。
- Validate movement failure observations separately from geometric route previews. Include known obstacles, compound player geometry, radius/tolerance mismatch, thin obstacles, narrow passages, scene changes and incomplete coverage. / 移动失败观察与几何路线预览分别验收，覆盖已知障碍、复合角色形状、半径/容差误差、细障碍、窄通道、场景变化及不完整覆盖。

## Ordered gates / 分段门

1. Complete product/Native builds, relevant regression, exact-source CI and real SDK/embedded-guide checks before installation. Maintain independent linear commits and normal main pushes. / 先完成产品/Native构建、相关回归、准确源码CI及真实SDK/内嵌指南核验，再安装；按独立线性提交正常推送main。
2. Qualify and install one coherent development cohort, preserve complete current save/protected records, and prepare the first necessary real operation before the normal launch. Retain the300-second startup hard limit and120-second target. / 同源开发程序合格并安装，完整保护当前存档/持久记录，开游戏前准备首笔必要实操；沿用300秒启动硬门与120秒目标。
3. First survey uses ordinary bounded movement plus public catalog/progression/inventory/geometry reads. It adds zero construction material allowance. Derive the actual test matrix and complete BOM from fresh facts. / 首轮仅正常有界移动及公开目录/科研/库存/几何调查，新增施工物料额度为0；依据新鲜事实列准确矩阵与整链BOM。
4. Existing material ceilings, cumulative spending, return/energy/warper reserves, one writer, original-action reconciliation and unknown quarantine remain applicable. An actual increment needs its exact consolidated Native-preflight/BOM decision before consumption. / 原物料上限、累计实耗、返航/能源/翘曲器储备、唯一writer、原动作核销及unknown隔离继续适用；实际增量在消费前完成准确集中原生预检/BOM决定。
5. Run one finite case at a time. Expected refusal passes only with no new prebuild/debit. Preserve every original accepted handle and post-check failures without refunding spent materials. / 逐个执行有限案例；预期拒绝须零新待建/扣料；保留所有原接受句柄，后置失败仍保留实际扣料。
6. Normally save/close/recover and continue one necessary operation. Verify every test stack and stock/function after recovery, recapture volatile physics handles and protect the final complete boundary. / 正常保存/退出/恢复并继续一笔必要实操；逐塔核对库存/功能，重新捕获易变物理句柄，保护最终完整边界。
