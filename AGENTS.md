# Spherewright-Lab working rules

## 推进方式 / How to run a scenario

- **整版倒推，只细化眼前一段。** 从最终能在游戏里看到的结果倒推科技、配方、库存、运输和供电。先启动已经就绪且耗时的科研或生产，等待时准备可独立做的工作。/ Work back from the in-game outcome through unlocks, recipes, stock, transport and power. Start long research or production early; use the wait for independent work. Detail the next bottleneck as it becomes relevant.
- **先跑通一条，再扩大。** 同一轮里可以连做建设、试料和观察，也可以顺手接好共用的带段。先看一份料从真实来源进入目标机器，再用连续产出判断整线是否跑通。下游立即取料时，同时看机器、分拣器和生产统计，不把仓内积存当作唯一成功信号；等待生产时并行推进其他环节。预览只说明有候选，首件只证明单次成功。/ Build, feed and observe in one run; connect shared belt segments together when convenient. Trace one item from its source into the intended machine, then look for repeated output from the full line. When downstream removes items immediately, use machine, sorter and production observations rather than waiting only for a stockpile; advance independent work while production runs. A preview, a first delivery and sustained production answer different questions.
- **遇阻先改做法。** 水上有可达的岸就正常走过去；移动未到精确位置但目标已在操作范围内，就直接继续。带口反复因同一原因不对齐，就换口、转弯或接已有带段。保守选址预测只是提示；具体原生准备可行时可分步建设，并实测供电和流转。若是工具误判，修正并回测受影响的路径，接着从已证现场推进。0.6 所需的合理科研、用料、施工和时长按[既有授权](operations/standing-authority.md)自行核算、记录和执行。/ Try an ordinary in-game alternative when the same obstacle recurs. If a move stops short but the target is already reachable, continue from there. Treat conservative site estimates as guidance: when actual Native preparation permits, build incrementally and observe power and flow. For a tool error, fix and verify the affected path and carry forward unaffected results. Use the existing Ascension grant for reasonable research, material, construction and runtime increments without a new approval.
- **交接只写一个“现在”。** 在[活动交接](operations/active-handoff.md)页首原位更新已证结果、当前卡点、下一步及其成功信号；按实际变化汇报，详细证据保留在对应场景。/ Update the top of the active handoff in place with the proven result, bottleneck, and next action with its observable outcome. Report what changed in game; keep dated evidence in the scenario.
